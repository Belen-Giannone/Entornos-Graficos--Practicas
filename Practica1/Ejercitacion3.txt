3.a
<a href="http://www.google.com.ar">Click aquí para ir a Google</a>
<a href="http://www.google.com.ar" target="_blank">Click aquí para ir a Google</a>
<a href="http://www.google.com.ar" type="text/html" hreflang="es" charset="utf-8" rel="help">
<a href="#">Click aquí para ir a Google</a>
<a href="#arriba">Click aquí para volver arriba</a>
<a name="arriba" id="arriba"></a>

- Diferencias en visualización:

El primer enlace abre Google en la misma pestaña.
El segundo abre Google en una nueva pestaña/ventana (target="_blank").
El tercero se ve igual que el primero, pero incluye atributos semánticos (type, hreflang, charset, rel) que no cambian la visualización, 
solo aportan información adicional.
El cuarto (href="#") no lleva a otra página, simplemente recarga la misma.
El quinto (href="#arriba") desplaza la vista hacia el marcador interno definido con <a name="arriba" id="arriba"></a>.

- Diferencias en visualización:
Primer caso: La imagen aparece primero y al lado un enlace textual “Click aquí”. La imagen no es clickeable, solo el texto.
Segundo caso: La imagen está dentro del enlace, por lo que al hacer clic en la imagen se abre Google. El texto “Click aquí” aparece

clickeables separadas).

- Conclusión:  
Aunque todos los ejemplos muestran una imagen y un texto, la diferencia está en qué parte es clickeable:
Solo el texto (primer caso).
Solo la imagen (segundo caso).
Imagen + texto juntos (tercer caso).
Imagen y texto en enlaces separados (cuarto caso).

3.c
- Diferencias en visualización:
Lista no ordenada (<ul>): Muestra los ítems con viñetas (●).
Lista ordenada (<ol> con varios <li>): Muestra los ítems numerados automáticamente (1, 2, 3).
Listas ordenadas separadas con value: Cada <ol> comienza un nuevo bloque, pero el atributo value fuerza la numeración (ejemplo: ítem “yyy” 
aparece como número 2, “ZZZ” como número 3).
Bloque de cita (<blockquote> con <p>): No es una lista real; el texto se muestra como un párrafo con saltos de línea y numeración escrita 
manualmente. Visualmente parece una lista, pero no tiene semántica de lista.

- Conclusión:  
Aunque todos muestran ítems, la diferencia está en cómo se presentan y cómo el navegador interpreta la estructura:
<ul> y <ol> generan listas semánticas con viñetas o números automáticos.
Usar value permite controlar la numeración manualmente.
<blockquote> solo simula una lista, pero no es reconocida como tal por el navegador ni por lectores de accesibilidad.

3.d
- Diferencias en visualización:
Primer caso:
Usa <th> para los encabezados de columna.
Los títulos aparecen automáticamente en negrita y centrados por defecto.
Las celdas de datos (<td>) se muestran alineadas a la izquierda.

Segundo caso:
No usa <th>, sino <td> con estilos manuales (<div align="center"><strong>…</strong></div>).
Esto obliga a centrar y poner en negrita el contenido de forma explícita.
Las celdas de datos también se centran gracias al <div align="center">.

- Conclusión:  
Ambos códigos generan tablas similares, pero:
El primer caso aprovecha la semántica de <th> para encabezados, lo que es más correcto y accesible.
El segundo caso fuerza la presentación con <div> y estilos, lo que da más control visual pero pierde semántica.
En navegadores modernos y para accesibilidad, se recomienda usar <th> para encabezados y CSS para estilos.

3.e
- Diferencias en visualización
Primer código:
El título se muestra encima de la tabla, separado del contenido, gracias a la etiqueta <caption>.
Las filas contienen celdas vacías con fondo gris (bgcolor="#dddddd").

Segundo código:
El título aparece dentro de la tabla, en la primera fila, ocupando las tres columnas gracias a colspan="3".
El texto se centra manualmente con <div align="center">.
Las filas siguientes también muestran celdas vacías con fondo gris.

- Conclusión
El primer caso usa <caption>, que es más semántico y accesible, ya que está pensado específicamente para títulos de tabla y 
se coloca automáticamente arriba.
El segundo caso fuerza la presentación del título dentro de la tabla usando colspan y estilos, lo que da más control visual 
pero pierde semántica.
En buenas prácticas modernas, se recomienda usar <caption> para títulos y CSS para estilos, porque mejora la accesibilidad y 
mantiene la estructura más clara.

3.f
- Diferencias en visualización
Primer código (rowspan):
La primera celda ocupa dos filas en la misma columna.
El título aparece verticalmente al lado de las celdas “Celda 1” y “Celda 2”, extendiéndose hacia abajo.

Segundo código (colspan):
La primera celda ocupa dos columnas en la misma fila.
El título aparece centrado horizontalmente sobre las dos celdas de la fila siguiente.

- Conclusión
Ambos ejemplos muestran cómo se pueden fusionar celdas en una tabla, pero con efectos distintos:
colspan combina columnas en una misma fila (horizontal).
rowspan combina filas en una misma columna (vertical).
Visualmente, el título cambia de posición: arriba ocupando todo el ancho (colspan) o al costado ocupando toda la altura (rowspan).
En buenas prácticas, se recomienda usar colspan y rowspan solo cuando sea necesario para organizar datos, y acompañarlo con CSS 
para mejorar la presentación.

3.g
- Diferencias en visualización
Primer código:
La tabla tiene bordes visibles (border="1") y un ancho de 200 píxeles.
No se definen cellpadding ni cellspacing, por lo que el navegador aplica los valores por defecto (espacio interno entre el contenido 
y el borde de cada celda, y separación entre celdas).
El título ocupa tres columnas (colspan="3") y está centrado con <div align="center">.
Las celdas se ven más separadas entre sí, con espacio interno visible.

Segundo código:
También tiene bordes y el mismo ancho, pero agrega cellpadding="0" y cellspacing="0".
Esto elimina el espacio interno y la separación entre las celdas, haciendo que los bordes se vean más juntos y compactos.
El título ocupa solo dos columnas (colspan="2"), por lo que la estructura es más angosta.
Visualmente, la tabla se ve más ajustada y con líneas más finas entre las celdas.

- Conclusión
La diferencia principal está en el espaciado interno y externo de las celdas:
El primer código usa los valores por defecto, mostrando una tabla con más aire entre los bordes y el contenido.
El segundo código elimina esos espacios con cellpadding="0" y cellspacing="0", logrando una apariencia más compacta.
Además, el uso distinto de colspan cambia la distribución del título: tres columnas en el primero, dos en el segundo.
En buenas prácticas modernas, se recomienda controlar estos aspectos con CSS (por ejemplo, border-spacing y padding) en lugar de 
atributos HTML, para mantener el código más limpio y flexible.

3.h 
- Diferencias en visualización y funcionamiento
Primer formulario:
Usa method="post" y action="procesar.php", por lo que los datos se envían al servidor para ser procesados.
Los campos están dentro de un <fieldset> con <legend>LOGIN>, lo que crea un recuadro con título.
El botón “Enviar” es de tipo submit, y abre el resultado en una nueva pestaña (target="_blank").
Visualmente, se ve más estructurado y profesional.

Segundo formulario:
Usa method="get", por lo que los datos se envían en la URL (visible en la barra de direcciones).
No tiene <fieldset> ni <legend>, por lo que se muestra sin recuadro.
Los campos están dentro de etiquetas <label>, lo que mejora la accesibilidad pero no cambia mucho la apariencia.
El botón también es submit, y abre el resultado en una nueva pestaña.

Tercer formulario:
Usa action="mailto:xx@xx.com", lo que intenta enviar los datos por correo electrónico en formato texto plano (enctype="text/plain").
El botón es de tipo reset, por lo que no envía los datos, sino que borra el contenido de los campos.
Visualmente, se parece al primero (usa <fieldset> y <legend>), pero su comportamiento es completamente distinto.

- Conclusión
Los tres formularios muestran campos para usuario y clave, pero difieren en cómo se envían los datos y en su estructura visual:
El primer formulario es el más funcional y correcto para un login real, ya que envía los datos al servidor mediante POST.
El segundo usa GET, útil para pruebas o búsquedas, pero inseguro para contraseñas porque los datos quedan visibles en la URL.
El tercero intenta enviar los datos por correo, lo cual no es habitual ni recomendable para formularios web; además, el botón 
“Enviar” no cumple esa función porque es de tipo reset.
En buenas prácticas modernas, se recomienda usar POST para formularios de login y manejar el envío con scripts del lado del 
servidor (PHP, Python, etc.), evitando mailto y GET para datos sensibles.

3.i 
- Diferencias en visualización
Primer código:
Usa la etiqueta <button>, que permite incluir contenido HTML dentro del botón, como imágenes (<img>) y texto con formato (<b>).
Visualmente, el botón muestra una imagen encima del texto “CLICK AQUÍ”, ambos dentro del mismo elemento clickeable.
Es más flexible, ya que se puede personalizar el contenido y el estilo del botón.

Segundo código:
Usa <input type="button">, que solo permite texto plano en el atributo value.
El botón muestra únicamente el texto “CLICK AQUÍ”, sin posibilidad de incluir imágenes ni formato interno.
Es más simple y rápido de implementar, pero menos personalizable.

- Conclusión
Ambos crean botones clickeables, pero difieren en flexibilidad y apariencia:
El primer botón (con <button>) permite combinar imagen y texto, ideal para interfaces más visuales o personalizadas.
El segundo botón (con <input type="button">) es más limitado, útil para acciones simples donde solo se necesita texto.
En buenas prácticas modernas, se prefiere <button> porque admite contenido HTML y es más accesible y adaptable a estilos CSS.

3.j 
- Diferencias en visualización y funcionamiento
Primer código:
Ambos botones de opción (radio) comparten el mismo atributo name="opcion".
Esto los agrupa en un mismo conjunto de opciones: el usuario solo puede seleccionar una de las dos (X o Y).
Visualmente, se muestran dos círculos vacíos con etiquetas “X” y “Y”, y al marcar uno, el otro se desmarca automáticamente.

Segundo código:
Cada botón tiene un nombre distinto (name="opcion1" y name="opcion2").
Al no compartir el mismo nombre, no están agrupados, por lo que el usuario puede marcar ambos simultáneamente.
Visualmente parecen iguales, pero funcionalmente actúan como controles independientes.

- Conclusión
La diferencia clave está en el atributo name, que define el grupo de selección:
Si los botones comparten el mismo name, forman un grupo y solo se puede elegir una opción.
Si tienen nombres distintos, funcionan como botones independientes, permitiendo seleccionar más de uno.
En buenas prácticas, los botones de tipo radio deben compartir el mismo name cuando representan opciones excluyentes dentro 
de una misma pregunta o categoría.
